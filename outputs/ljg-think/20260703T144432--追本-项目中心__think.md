# 追本：项目中心从人迁到 Agent

## 第一层——使用方式

表象是「人在指挥 Agent」。
我开口，它做；我检查，我再开口。我是发动机。

但作者说：不是。这是过渡态。真正的形态是——人从中心走出来，站到系统上方。Agent 系统成为发动机，人只在需要判断的那一刻现身。

这一层看上去是工作方式的调整。
裂缝：人为什么要从中心让出来？

## 第二层——注意力瓶颈

因为人天生是个单线程的注意力瓶颈。
项目推进的每一步都需要判断，判断必须回到人，所以项目跑多快取决于人一天能做多少次判断。这是硬上限。
Agent 在工程层面把任务变长，看上去是效率提升；但只要"判断"还是必经关卡，效率提升永远只能到"一个人配几个助手"这种线性边界。

Loop 真正想撬的，是这道关卡：把"做"和"判断"拆开，人只做后者，前者归系统。

这一层是注意力经济学。
裂缝：但"让系统自己跑"听起来像把决策权交出去——人凭什么愿意交？

## 第三层——复利资产

因为交出去的判断不是一次性消耗品，是资产。
人给 Agent 的每一次拍板，它都收下、记住，下一次自己就用上了。带员工的比喻是对的，但带完员工的人会走；Agent 沉淀的判断永远留在系统里。

作者把这个叫"利滚利地变厚"——纳德拉讲的"人和 AI 之间复利的学习"说的也是这件事。一次判断不是一次决策，是一次对未来所有同类决策的默认规则投资。

这一层是资产视角：Loop 不是工具，是存款账户。
裂缝：那为什么要"以项目为中心"而不是"以任务为中心"？任务也能存判断啊。

## 第四层——语境锁定

任务是离散的，项目是连续的。
"帮我发封邮件"是任务，"帮我盯着这个电商店"是项目。只有连续的语境里，判断才有复用的土壤——每一次异常、每一次顾客反馈、每一次供应商延误，都是同一套规则的打磨素材。

任务中心的 Agent 永远是打零工的；项目中心的 Agent 才能"越来越懂你"。
Dittos Loop 想做的 loopable——让 Agent 自己识别"这件事以后还要反复出现"——本质是让系统自己把离散任务打包成连续项目。

这一层是颗粒度：项目是复利的容器。
裂缝：如果判断存进系统可以复利，那这些判断算谁的？

## 第五层——经验的可传递性

过去，一个人在一个项目里琢磨出来的门道，锁在他脑子里。
他走了，项目就瘫一半；新人来，得从头学。经验是人的私产，不可复制、不可移交、不可继承。这是组织效率的万年瓶颈。

当判断被 Agent 沉淀为系统规则，经验第一次变成**可复制的公共品**——它能原样交给下一个接手的人，能同时跑在多个项目上，甚至能被"出售"给陌生人（你可以把运转的 Project OS 整个交给别人）。

普通人的门道第一次能"攒起来、传下去"。这才是文章里说的"最动人的地方"。

这一层是所有权重构：经验从人的私产变成系统的资产。
裂缝：这听上去像在替人做判断——人被架空了吗？

## 第六层——决策的稀缺性

恰好相反。人不是被架空，是被提纯。
当所有"做"的环节、可复用的判断、常规异常处理都从人身上剥离，剩下给人的只有那类真的不可压缩的判断——价值观层面的选择、方向层面的拍板、不可预测的十字路口。

人从"项目里那个不停转的齿轮"变成"只在关键路口出现的决策者"。
齿轮是消耗品，决策者才是稀缺品。

Loop 最终给人的不是"少干活"，是"只干只有你能干的活"。

## 底层——分工的终点

再往下问：为什么"只有人能做的判断"会存在？

因为 AI 没有 stakes（赌注）。
判断的本质是承担后果。"这个 bug 先放一放"、"这个客户退款算了"、"这条线放弃"——这些判断之所以是人做，不是因为 AI 算不出来，是因为承担后果的是人，不是 AI。

只要 stakes 在人身上，最终判断权就在人身上。
Loop 不是要取代这个，是把人从不需要 stakes 的判断里解放出来，让他把全部注意力押在真正要承担后果的地方。

这是最底层的真相：AI 接管执行和可复用判断，人退回 stakes 所在——这不是人让出位置，是人找到自己真正不可替代的位置。
