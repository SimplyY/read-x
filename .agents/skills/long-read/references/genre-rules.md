# 文体专项规则

专项规则改变摘要结构、信息筛选方式、默认输出长度、是否适合进入 Deep、是否适合视觉化。**专项规则不得绕过 evidence 层**：先提取证据，再按文体筛选。

## 目录

1. 阮一峰《科技爱好者周刊》
2. 短篇小说
3. 深度访谈/Q&A
4. 数据报告
5. 李继刚《人生周报》

## 1. 阮一峰《科技爱好者周刊》

**识别标志**（满足任一）：
- 标题含「科技爱好者周刊#」「阮一峰」
- 作者为「阮一峰的网络日志」
- 内容结构含「科技动态」「文摘」「文章」「工具」「资源」「一句话新闻」等固定小标题

**处理规则**（覆盖默认 article-decode + 深度链路）：周刊是每周固定高频流程。USER.md 只用于**筛选层**（决定保留哪些板块、去掉哪些无关内容），不用于正文层逐条贴用户画像标签。正文忠实呈现已保留的内容，不泛泛罗列、也不逐条论证「跟你 XX 相关」。

```
📖 《周刊标题》(第X期)

## 🎯 科技动态 · 精选（1~3 条）
从「科技动态」「一句话新闻」中挑值得看的 1~3 条。
每条格式：标题 + 一句话摘要 + 为什么值得看

## 📄 文摘
保留原文要点并提炼核心，保留原文表达，不泛泛改写。

## 💬 言论（全量保留）
逐条保留原文，不筛选、不压缩、不改写。

## 📚 其他章节
只列值得记的文章/工具/资源（标题 + 一句话价值），不凑数。
```

**限制**：
- 不走默认深度链路（周刊是杂志体，不需要概念深钻或多维解剖）
- 不走默认 article-decode（周刊内容天然碎片化，不适合按单一精神结构解码）
- 用卡片回复（`--as bot`，符合 link-card），不生成飞书文档
- 卡片要充实但不硬凑：重点内容全量囊括，不为压缩丢信息；字数上限约为普通精读卡片的 1.5 倍，不是目标值
- 言论全量保留，不按画像筛选、不压缩、不改写
- **相关性约束（硬）**：正文不逐条贴用户画像标签（禁止「跟你『着力即差』相关」「正是『AI 是剑不是茧』的落地」之类）。USER.md 只在筛选层决定取舍；全文最多在主题段或最值得深读的一处点明与用户关注的核心联系，其余板块一律不贴。

**是否适合 Deep**：不适合（杂志体，碎片化）
**是否适合视觉化**：不适合

## 2. 短篇小说

**识别标志**：
- 标题含「小说」「故事」「虚构」
- 正文以叙事为主，有人物、情节、场景

**处理规则**：
- evidence 层提取：情节、主题依据、值得细品的原文段落（每段绑定原文）
- 输出包含：故事一句话、主题解读、值得细品的段落
- Deep 时优先 `ljg-writes`（批评短文）或 `ljg-think`（主题深钻），按内容适配选择，不强制

**是否适合 Deep**：适合（主题深钻有价值时）
**是否适合视觉化**：一般不适合

## 3. 深度访谈/Q&A

**识别标志**：
- 正文以对话/Q&A 形式为主
- 标题含「对话」「访谈」「问答」

**处理规则**：
- 不生成「骨架」章节
- evidence 层提取：核心观点（每条绑定发言人和原文）、金句
- 输出「核心观点碰撞」：本质是快速总结，只放核心观点 + 金句，不铺陈背景和过程
- 每条观点一句话讲清；金句逐字保留原文，不扩写、不改写、不加「这说明…」式二次解读
- 反常识判断单独拎出，同样一句话，不展开论证
- 宁少勿多：读完记住几个点 + 几句金句即可，不为「完整」堆字


**是否适合 Deep**：适合（核心判断提炼有价值时）
**是否适合视觉化**：内容有多角色/利益方时适合（按内容适配，不强制）

## 4. 数据报告

**识别标志**：
- 有大量数据、图表、对比表格
- 标题含「报告」「研报」「数据」

**处理规则**：
- 不生成「骨架」章节
- evidence 层必须区分：原始数据、报告结论、模型解读（三者来源不同，不得混淆）
- 附一张关键数据表
- Deep 时若内容天然适合视觉化（多维度数据对比），考虑 `ljg-card -i`，按内容适配选择，不强制

**是否适合 Deep**：适合（数据背后的因果或趋势分析有价值时）
**是否适合视觉化**：天然适合（多维度数据对比），但仍需内容适配，不因质量分强制

## 5. 李继刚《人生周报》

**识别标志**（满足任一）：
- 标题含「人生周报」且作者为「李继刚」
- 正文结构含「## 读」「## 说」「## 书」等固定小标题，且标题含「人生周报」

**处理规则**（覆盖默认 article-decode + 深度链路）：李继刚人生周报是固定栏目（好句子合集，读/说/书三块）。与阮一峰周刊同属专项快通道，但处理方式不同：不按板块全量展示，而是**按用户画像筛选句子**。

- USER.md 只用于**筛选层**：按用户兴趣域（AI 与创作/教育、价值投资、判断力、内在秩序、健康、诗意）从三块中各挑与该周主题相关的句子
- **筛选硬约束（核心）**：至少筛掉一半内容——按原文内容单元（每个出处块/每条句子算一个单元）计数，入选单元数 ≤ 原文单元总数的一半（向下取整）。不是靠省略凑字数，而是先筛掉一半，留下的整句呈现。
- 筛选标准 = 兴趣相关 × 句子可迁移（脱离原文仍有力、能带走）
- **结构必须与原文一致**：按原文板块「读 / 说 / 书」组织，板块内按原文顺序；不按主题重组、不打散顺序，用户对照原文能快速定位
- **原句逐字保留（默认硬约束）**：入选句子默认原样引用原文，含标点与分行，一字不改；
  禁止无标注压缩、改写、转述、摘要、合并、润色。英文原句保留英文原文，中文只作附注、不得替代原文。
  只允许两种操作：整句保留或整句剔除，再①按原文板块顺序组织、②加极短（≤15 字）点睛标注。
- **列表排版（硬）**：卡片条目用列表（`-`）逐条呈现，不用段落整块；每条一个列表项，密集但可扫。
- **原文定位（硬）**：不加板块内序号（「读 2」「说 1」式序号反而不好对照原文）；尾部保留出处（如「即刻 @xxx」「X @xxx」）作为定位锚点，用户凭出处对原文快速定位；卡片标题不标注序号说明。
- **换行与原文一致（硬）**：长条目（如书部分完整段落）换行呈现跟原文分行一致，不加两个句号「。。」之类标记；原文一段就整段一条，原文分行就分行。
- **书部分完整（硬）**：书板块（本周推荐书籍、核心引言段、作者主方法、四环）无论多长都完整逐字保留，不省略、不附概要；引用「普通决策把环境当成不回应的树林……把众人推向哪里」这类引言段不得遗漏。
- **说部分按原文分行（硬）**：原文多行的条目（如「创作 = 创 + 作」后接「人来负责『创』（出题）」「ai 负责『作』(解题)」）按原文分行呈现，不挤成一行。
- **省略号省略（唯一的截断方式，不是压缩）**：单句/段落超过 200 字时才可省略；≤200 字必须整句逐字保留或整句剔除。省略规则：
  - 最核心的内容逐字保留，不核心的中间内容用省略号「……」省略，省略处必须有省略号，读者能看出删了内容
  - 禁止压缩改写：不重写语句、不合并、不润色措辞，只做「保留核心 + 省略号代替被删部分」
  - 省略后紧跟括弧标注「（省略了 xx%）」，xx = round(省略字数 ÷ 原句字数 × 100)，占比必须如实、宁高勿低
  - **省略 >50% 必须附概要式介绍**：省略比例超过 50% 时，省略号+标注不够，读者不知道被删内容，须在标注后另起一行用小字「概要：……」一句话概括被省略部分的核心含义，让读者不看原文也能懂；≤50% 不需概要
  - 其余未省略句子保持逐字原样
  反例（禁止）：无省略号直接改写/压缩一律禁止；英文原句 Your attention is someone else's business model. 不得只给中文「你的注意力是别人的商业模式」；≤200 字句子不得省略。
  不逐条贴画像标签论证
- 保留原文链接

**限制**：
- 不走默认深度链路、不走 article-decode（句子合集，天然碎片化）
- 用卡片回复（`--as bot`，符合 link-card），不生成飞书文档
- 篇幅由「筛掉一半」（见上）自然控制，不再以 50% 字数为硬约束；单条句子不扩写、不改写原文（原句逐字保留硬约束见上）
- **相关性约束（硬）**：正文不逐条贴「跟你『着力即差』相关」式标签；分组标题已表达主题，点睛标注最多一处，不铺陈

**是否适合 Deep**：一般（句子合集，筛选为主；当周主题值得深钻时单独评估）
**是否适合视觉化**：不适合
