# long-read: 长文精读

收到一篇长文，拆成三段式精读摘要，再根据内容自动选择合适的 ljg 深度链路产出附加价值。结果短的直接回群，长的生成飞书文档。

## 工作流概览

```
用户发链接/粘贴长文
  │
  ├─ [0] 来源适配 → 获取正文/拉取仓库
  │    ├─ GitHub 仓库 → learn（深度研究）/ summarize（轻量）→ [3] 输出
  │    └─ 文章类      ↓
  ├─ [0.5] 文体识别 → 专项/默认
  ├─ [0.7] 用户画像参照（判断重要性/长度/金句）
  ├─ [1] 三段式精读摘要（必做）
  ├─ [2] ljg 深度链路判断（自动选择，每次最多 3 条）
  └─ [3] 输出路由 → 群内回复 / 飞书文档
```

## [0] 来源适配

| 来源 | 方法 |
|------|------|
| GitHub 仓库 URL（`github.com/<owner>/<repo>`） | 见下方 GitHub 仓库专项 |
| `mp.weixin.qq.com` | 使用 `wechat-article-to-markdown` skill 直接抓取（最快路径，不要用其他方式） |
| 飞书文档 URL（`feishu.cn`/`larksuite.com`） | 使用 `lark-doc` skill 读取 |
| 其他网页 URL | 使用 `read` skill 获取 |
| 纯文本粘贴 | 直接使用 |

### GitHub 仓库专项

识别：URL 形如 `https://github.com/<owner>/<repo>`（含 tree/blob 子路径），或用户发 `owner/repo` 简写。

**处理规则**：
- 判断用户意图：
  - 发仓库链接 + 无额外说明 → 默认**深度研究**，走 `learn` skill 六阶段工作流，用 GitHub MCP 拉取代码和元数据（README、目录结构、核心模块、关键文件），输出结构化报告（项目定位、架构、核心模块、设计意图、关键流程、star 数/活跃度等）
  - 明确说"快速看看""简单总结""README" → 走 `summarize` skill，轻量总结 README 和基本信息
- 深度研究产出较长，生成飞书文档回群
- 轻量总结可直接群内回复
- 仓库内容不做三段式精读摘要（那是给文章用的），按 learn/summarize 的输出格式走

---

获取后检查字数（GitHub 仓库和专项文体不适用此检查）：
- `< 800 字`：跳过完整拆解，直接给一句话摘要（太短不值得精读）
- `≥ 800 字`：走完整流程

## [0.5] 文体识别与专项处理

收到内容后，先判断文体类型。如果是以下特殊文体，跳过默认三段式精读 + ljg 深度链路，按专项规则处理。

### 识别流程
```
扫描标题、作者、内容结构
  ├─ 阮一峰/科技爱好者周刊 → 周刊专项
  ├─ 短篇小说/故事体        → ljg-writes 或 ljg-think
  ├─ 深度访谈/Q&A           → ljg-think + ljg-card
  ├─ 数据报告/研报           → ljg-card -i
  └─ 以上都不是              → 走默认流程 [1]→[2]→[3]
```

### 阮一峰《科技爱好者周刊》专项

**识别标志**（满足任一即触发）：
- 标题含"科技爱好者周刊#"、"阮一峰"
- 作者为"阮一峰的网络日志"
- 内容结构含"科技动态""文摘""文章""工具""资源""一句话新闻"等固定小标题

**处理规则**（覆盖默认三段式 + ljg 链路）：

```
📖 《周刊标题》(第X期)

## 🎯 科技动态 · 精选（1~3 条）
从"科技动态""一句话新闻"中挑选与用户最相关的 1~3 条。
用户关注优先级（从高到低）：
  1. AI 大模型 / Agent 能力演进
  2. AI 商业化 / Token 价格
  3. 中国科技 / AI 芯片 / 制造
  4. 工具与生产力 / 工作流
  5. 其他
每条格式：标题 + 一句话摘要 + 为什么值得看

## 📄 文摘（全量保留）
按原文顺序列出周刊里所有文摘段落。
不压缩、不改写、不挑选——保留原文表达和结构。
仅去除广告/免责声明/无关图片等噪声。

## 📚 其他章节（简短索引）
- 文章：X 篇（仅列标题）
- 工具：X 个（仅列名称）
- 资源：X 个（仅列名称）
——不展开，用户感兴趣可再追问
```

**限制**：
- 不走默认 ljg 深度链路——周刊是杂志体，不需要概念深钻或多维解剖
- 不走默认三段式精读骨架——周刊内容天然碎片化，骨架化没有意义
- 飞书群内直接回复（即使稍长），不生成飞书文档

### 短篇小说专项

**识别标志**：
- 标题含"小说"、"故事"、"虚构"
- 正文以叙事为主，有人物、情节、场景

**处理规则**：
- 不走三段式骨架（小说不能被"核心论点"拆解）
- 优先走 ljg-writes（批评短文）或 ljg-think（主题深钻）
- 输出包含：故事一句话、主题解读、值得细品的段落

### 深度访谈/Q&A 专项

**识别标志**：
- 正文以对话/Q&A 形式为主
- 标题含"对话"、"访谈"、"问答"

**处理规则**：
- 不走三段式骨架
- 优先选 ljg-think（提炼核心判断）+ ljg-card（信息图）
- 输出核心观点碰撞、反常识判断

### 数据报告专项

**识别标志**：
- 有大量数据、图表、对比表格
- 标题含"报告"、"研报"、"数据"

**处理规则**：
- 不走三段式骨架
- 优先 ljg-card -i 生成信息图 PNG
- 附一张关键数据表

## [1] 三段式精读摘要（必做步骤）

摘要长度**弹性决定**——根据文章质量、深度、与用户关注主题的匹配度决定写多长，不要把高质量内容压碎：

- **短文/水文/通稿**（< 1500 字 或 无深度）：一句话 + 骨架（≤3 条）+ 0~1 条值得记住，总计约 200 字以内
- **中等质量文章**（常规科技/工具/观点文）：一句话 + 骨架（3~5 条）+ 2~4 条值得记住，总计 200~500 字
- **高质量长文/重要文章**（深度分析、一手访谈、用户高关注主题的核心文章、8000 字以上好文章）：一句话 + 骨架（5~8 条，每条可写 1~2 句说明，不是只有 15 字的干瘪标题）+ 4~8 条值得记住（含原文金句），总计 500~1000 字
- **特别重要的文章**（直接击中用户核心关切，或经典级文章）：可以超过 1000 字，但每句话都必须有信息增量，不要注水

**双维度评分**（放在摘要最前面，一眼判断读不读、读多深）：

维度一：**文章质量分**（先看内容本身的完成度、深度、逻辑、信息密度；然后叠加来源加权——不以是否原创简单加减分，但一手亲历者的判断力密度天然高于二手观察）：

**内容基础分**（四个子维度分别打分，每个 0.5 粒度，再取平均，保留一位小数）：

| 子维度 | 测什么 | 10 分长什么样 |
|--------|--------|-------------|
| 完成度 | 文章是否自洽？论点是否有充分论证支撑？有没有关键环节缺失？ | 每个论点都有证据/例子/数据支撑，逻辑闭环，读完不觉得「这里没展开」 |
| 深度 | 触及本质还是浮在表面？有没有反常识判断？有没有超越行业共识的洞察？ | 读完后对这件事的理解框架被改变了，不是「知道更多」而是「重新理解」 |
| 逻辑 | 论证链条是否严密？因果是否清晰？有没有偷换概念或逻辑跳跃？ | 每段推理都可以追溯，反驳也能预判，读起来像数学证明一样干净 |
| 信息密度 | 每 100 字的信息增量？有没有注水、重复、套话、正确的废话？ | 几乎没有可以删掉的句子，每段都有新信息，读完觉得「这篇值得再读一遍」 |

**基础分 = (完成度 + 深度 + 逻辑 + 信息密度) ÷ 4**，保留一位小数（如 8.3、7.8、9.0）。

**⚠️ 粒度硬性约束（最高优先级，违反即不合格）**：
- 每个子维度必须精确到 0.5（允许的值：0.5、1.0、1.5、2.0……9.5、10.0），**禁止使用 7、8、9 等裸整数**（应写 7.0、8.0、9.0）
- 最终质量分保留一位小数，**禁止四舍五入到整数**——8.3 就是 8.3，不要写成 8；8.9 就是 8.9，不要写成 9
- 8.3 和 9.3 是截然不同的文章质量——不要因为「看起来差不多」就合并
- **评分后必须自查**：四个子维度是否都精确到了 0.5？如果四个子维度全是 X.0 没有 X.5，说明粒度不够细，至少两个子维度应带 .5

**基准参考**（帮助校准）：
- 钟十六 Loop 文：完成度 8.5、深度 8.5、逻辑 8.0、信息密度 8.0 → 基础分 8.3
- 李开复访谈：完成度 8.5、深度 8.5、逻辑 8.0、信息密度 8.0 → 基础分 8.3
- 普通科技教程/工具文：完成度 7.0、深度 6.5、逻辑 7.0、信息密度 6.5 → 基础分 6.8
- AI 通稿/软文：完成度 5.0、深度 4.0、逻辑 5.0、信息密度 4.0 → 基础分 4.5
- 水文/标题党：完成度 3.0、深度 2.0、逻辑 3.0、信息密度 2.0 → 基础分 2.5

**来源加权**（在基础分上叠加，上限 10 分）：
| 条件 | 加权 |
|------|------|
| 作者是事件/判断的第一亲历者（创始人/CEO/核心决策者），非第三方观察者 | +1.0 |
| 文章包含真实商业决策、失败反思、一手数据、具体代价（非抽象分析或二手综述） | +1.0 |
| 两项同时满足 | 上限 +1.0（不叠加，一手自述不能天然满分） |

最终质量分 = 内容基础分 + 来源加权，上限 10 分。

**评分输出格式**（必须在摘要中显式写出，让评分过程可追溯）：
`质量 8.3/10（完成度 8.5 + 深度 8.5 + 逻辑 8.0 + 信息密度 8.0 → 基础 8.3 + 来源加权 +1.0 = 9.3）`

**来源加权为什么重要**：同一篇关于企业 AI 转型的文章，记者写的和创始人写的，在「完成度」上可能同分，但后者每句话都是真金白银换的。李开复说「放弃万亿参数基模」——这不是分析，是 2025 年他亲手裁了一大批基模研究员之后做的决定。这种判断力密度，基础分里体现不出来，必须加权。

维度二：**对我有用分**（结合用户画像和当前关注的主题判断对"这个用户"的价值——同一个内容对不同人有用度完全不同）：
- ★★★★★：直接命中当前项目/近期思考/反复问过的问题，读完立刻能用
- ★★★★：和当前关注领域强相关，有可借鉴的思路或方法
- ★★★：有一定参考价值，但不是当前优先事项
- ★★：有点意思但暂时用不上
- ★：无关内容，可跳过

**评分→深度链路数量（按最终质量分和"对我有用分"取高者决定）：**
- 质量 ≤4.0 或 有用 ≤★：不调用 ljg，一句话带过
- 质量 5.0~6.9 或 有用 ★★：0~1 条 ljg
- 质量 7.0~7.9 或 有用 ★★★：1~2 条 ljg（视内容饱满度决定）
- **质量 8.0~8.9 或 有用 ★★★★：2 条 ljg**（如 ljg-think + ljg-qa 问答链，或 ljg-think + ljg-card 信息卡）
- **质量 ≥9.0 或 有用 ★★★★★：3 条 ljg**（用完互补配额）

评分不是凑数——质量 4.0 以下压到 100 字以内，别浪费读者时间。评分时必须在「摘要」段内显式写出四个子维度分、基础分、来源加权和最终分，例如：`**基础 8.3 + 来源加权 +1.0 = 9.3 分**`，让评分过程可追溯。

**结构**：

```
📖 《文章标题》

【评分】质量 8.3/10（完成度 8.5 + 深度 8.5 + 逻辑 8.0 + 信息密度 8.0 → 基础 8.3 + 来源加权 +1.0 = 9.3）· 有用度 ★★★★★

【一句话】这篇文章在说什么——20~50 字，说清核心论断或独特贡献，不要写"本文介绍了……"这种空话

【骨架】
▸ 论点 1（可附一句解释，说明为什么这个论点重要/新）
▸ 论点 2
▸ ……
（中等文 3~5 条，高质量文 5~8 条；每条不必限于 15 字，说清为主）

【值得记住】
- 🔢 关键数据/例子（带原文引用）
- 💡 反常识判断/核心论断（逐字保留原文金句，不要改写）
- 🛠 可带走的方法论/判断框架
- ✍️ 有力度的原文金句（逐字保留）
（短文 ≤3 条，中等文 3~5 条，高质量文 5~8 条）
```

**约束：**
- **宁长勿碎**：高质量文章的摘要不要为了短而砍掉有价值的论点、例子、金句。用户之后回看笔记时，摘要本身应该能唤起记忆、独立可读
- **禁止编造**：不编造原文不存在的观点、数据、例子；金句必须逐字核对原文
- **加粗规则：** 骨架中的核心概念、值得记住中的关键句/金句、方法论关键字，必须加粗
- **段落长度：** 单段不超过 150 字；超过则拆段，每段只讲一个点
- **金句逐字保留：** 符合金句保留规则的原文句子，必须用引号或引用格式逐字保留，不得改写、压缩、转述
- **判断标准：** 问自己——"用户读完这条摘要，是否能知道这篇文章值不值得深读？哪些句子他可能想划出来？"如果摘要读完感觉什么都没说，那就是写得太短了

## [2] ljg 深度链路（自动判断）

扫描摘要骨架，判断内容最适合哪条深度链路。每次最多选 **3 条**（互补搭配，见下文搭配策略）。

### 匹配规则

| 内容特征 | 匹配链路 | 输出形式 |
|-----------|---------|---------|
| 提出一个核心概念/理论/术语 | `ljg-think` — 钻到根 | 思考链短文 |
| 覆盖多个维度或层次/可解剖 | `ljg-learn` — 八维解剖 | 结构洞察 |
| 争议性论述/可辩论 | `ljg-roundtable` — 多角度碰撞 | 辩论链 |
| 反常识/值得批判的立场 | `ljg-writes` — 批评短文 | 1500 字短文 |
| 逻辑链长/层层递进 | `ljg-qa` — 问答链 | QA 链 |
| 以上都不明显 | 不调用 ljg | 纯摘要 |

**判断规则：**
- 先扫骨架，看有没有一个突出的**核心概念**或**独特术语** → `ljg-think`
- 如果文章有多维度展开（经济学/心理学/历史等多角度） → `ljg-learn`
- 如果文章内容深度很高时 → `ljg-roundtable`
- 如果文章在清晰解释一个罕见概念/单词 → `ljg-word`
- **不堆砌**——优先选 1-2 条，内容重要且复杂时可选 3 条
- **不确定时不调**——纯摘要已经足够

### Skill 搭配策略


**互斥搭配（不要同时选）：**
- `ljg-think` + `ljg-learn`（重叠太多，都是结构分析）
- `ljg-roundtable` + `ljg-qa`（都偏逻辑链，选一个即可）
- `ljg-word` + 其他（ljg-word 太专，独立使用）

多 Skill 产出时需合并到同一篇飞书文档，摘要在前，skill 各占一个大标题。

## [3] 输出路由

| 条件 | 输出方式 |
|------|---------|
| 纯摘要（无 ljg 产出）+ 总长度 ≤ 15 行 | 群内直接回复（markdown） |
| 含 ljg 长文本 + 摘要总共 > 15 行 | **必须**生成飞书文档 → **立即自动回群发完成卡片**，不要等用户问 |
| 含 ljg 短文/QA/思考链 | **必须**生成飞书文档 → **立即自动回群发完成卡片**，不要等用户问 |

**⚠️ 飞书 bridge 环境强制规则：创建完飞书文档后，必须在同一轮里自动发送完成消息回群，绝不等用户催。**

生成飞书文档 + 回群流程：
1. 写完精读内容到本地临时 markdown 文件
2. 用 `lark-cli docs +create --title "[精读] 《原文标题》" --content @.wx_doc.md --doc-format markdown --parent-position my_library` 创建文档（必须在项目根目录 cwd 下执行，用相对路径 @ 引用）
3. 创建成功后**立即**用 `lark-cli im +messages-send --chat-id <bridge_context.chatId> --markdown "..."` 回群发完成消息
4. 清理临时文件（`.wx_tmp.md`、`.wx_doc.md`）
5. 文档内容：三段式摘要在前，各 ljg 产出分节在后，末尾附原文章链接

回群完成消息格式（markdown，控制在 10 行以内）：
```
**精读完成 ✅**

📄 <飞书文档链接>

- **评分：质量 8.3/10（完成度 8.5 + 深度 8.5 + 逻辑 8.0 + 信息密度 8.0 → 基础 8.3 + 来源加权 +1.0 = 9.3）· 有用度 ★★★★★**——一句话说明为什么是这个分
- **X 条 ljg 链路**：`ljg-xxx`（一句话说挖了什么）+ `ljg-xxx`（一句话）
- **冷抓取 Xs，总耗时约 Xs**
```
